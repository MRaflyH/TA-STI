# Tugas Akhir — GFD Prediction with Quantum Machine Learning

Ground flash density (GFD) prediction for tropical (West Java) and subtropical
(Florida) domains, using a variational quantum neural network in Qiskit, plus
the data pipeline that builds its training tables and the modelling code that
consumes them.

Muhammad Rafly (18222067) — Sistem dan Teknologi Informasi, STEI ITB (II4092).

This repository holds three things that are worked on independently: the
**thesis document** (`paper/`), the **data pipeline** (`dataset-pipeline/`), and
the **modelling experiment** (`modelling/`).

Three rules that are easy to violate by accident:

1. `paper/Template Baskara/` is an unmodified copy of the upstream template. It
   is there to check formatting and canonical file names against. Nothing is
   ever written into it, and its `daftar-pustaka.bib` is dummy data that must
   never be cited.
2. `dataset-pipeline/data/raw/` is precious and irreplaceable — the PLN records
   are not public. `data/processed/` is regenerated by one command and safe to
   delete. Neither is in git.
3. **`make_fake_table.py` output is fake.** Every table it writes carries
   `"synthetic": true` in its `.meta.json` and the flag survives into
   `modelling/results/*.json` as `build_meta.synthetic`. Check that field before
   reading any metric. No synthetic number may reach the thesis.

## The thesis (`paper/Rafly TA/`)

XeLaTeX with Biber. `pdflatex` and `bibtex` will not work.

### Setup (macOS)

```bash
brew install --cask mactex-no-gui
```

The full distribution, not BasicTeX — the preamble loads `algorithm`,
`biblatex-chicago`, `threeparttable`, `datetime2-bahasai` and others that
BasicTeX does not ship. Open a new terminal afterwards so `xelatex` is on the
PATH. Nothing else is needed; `biber` and `latexmk` come with it, and
`\setmainfont{Times New Roman}` resolves from macOS system fonts.

### Compiling

From the directory holding `TA.tex` — not a subdirectory, since every `\input`
and `images/` path is relative to it:

```bash
cd "paper/Rafly TA"
latexmk -xelatex -file-line-error -interaction=nonstopmode TA.tex
```

`latexmk` reruns xelatex and biber until the cross-references, table of
contents, and bibliography stop changing. Doing it by hand is the same four
passes in a fixed order:

```bash
xelatex TA.tex
biber TA          # job name, no extension
xelatex TA.tex
xelatex TA.tex
```

`latexmk -C TA.tex` clears the build state if a compile starts behaving oddly.

`TA.tex` is the driver for the Tugas Akhir report (II4092, Bab I–VII).
`ProposalTA.tex`, if present, is the older proposal template (II4091, Bab I–V) —
the two have different geometry, frontmatter, and float conventions, so check
which one you are editing before matching a convention.

`daftar-pustaka.bib` in this folder is the only bibliography.

## The dataset pipeline (`dataset-pipeline/`)

Reads lightning strike records and meteorological data from four sources,
aggregates everything onto a common 0,5° grid at the resolution set by
`config.TIME_FREQ` — currently **hourly** — and writes one table per climate
domain.

| Source | Role | Domain | Status |
|---|---|---|---|
| PLN Puslitbang LDS | strike records → GFD target | tropis | complete, 2018–2024, 2.242.100 CG strikes |
| NASA MERLIN (KSC archive) | strike records → GFD target | subtropis | complete, 89 exports, 5.301.491 strikes — but 5 exports returned nothing and 3 months are missing |
| NASA POWER | surface meteorology predictors | both | complete, 591 files |
| ERA5 (Copernicus CDS) | thermodynamic predictors | both | complete, 168 files — but `KX` is absent from subtropis |

Both processed tables are built: `gfd_tropis_hourly.parquet` (1.841.040 rows,
14 features) and `gfd_subtropis_hourly.parquet` (3.314.304 rows, 13 features).

Full acquisition instructions, request counts, and the validation log are in
`RUNBOOK.md`. Read it before running anything that costs network requests — the
POWER fetch is ~590 requests and the ERA5 fetch is 168 queued ones. The
"Still unverified" section at the end is the list of things that have to reach
the thesis as limitations rather than be quietly assumed away.

### Setup

```bash
cd dataset-pipeline
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt truststore
```

Every command below runs from `dataset-pipeline/src/`, with the venv active.
Running from the repo root gives `ModuleNotFoundError: No module named
'gfd_data'`.

### Running

```bash
cd src

# 0. lightning checks -- no network, run these first
python3 -m gfd_data.smoke_lightning        # timezone sanity + monthly coverage

# 1. lightning download (MERLIN needs a device-level VPN with a US exit)
python3 -m gfd_data.merlin_download --start 2018-01-01 --end 2024-12-31

# 2. meteorology -- smoke-test each before the bulk download
python3 -m gfd_data.smoke_power
python3 -m gfd_data.power

python3 -m gfd_data.smoke_era5     # needs ~/.cdsapirc, see RUNBOOK step 4
python3 -m gfd_data.era5

# 3. one-month end-to-end test, then the real build
python3 -m gfd_data.smoke_build
python3 -m gfd_data.build
```

Output: `data/processed/gfd_<domain>_<resolution>.parquet` and `.meta.json`
(a config snapshot so the build can be replayed). A `.csv` mirror is written
only below 500 000 rows, or with `--force-csv`. At hourly resolution the
filenames are `gfd_tropis_hourly.*` and `gfd_subtropis_hourly.*`.

Downloads cache by filename, so re-running skips whatever already succeeded.
PLN workbooks are placed in `data/raw/pln/` by hand; there is no downloader.

### Useful flags

```bash
python3 -m gfd_data.build --no-power --no-era5      # lightning only
python3 -m gfd_data.build --force-csv               # CSV above the row limit
python3 -m gfd_data.smoke_lightning --domain tropis --month 2024-01
python3 -m gfd_data.smoke_build --no-fetch          # use only what is on disk
python3 -m gfd_data.merlin_download --self-test     # check the URL codec
python3 -m gfd_data.merlin_download ... --dry-run   # list windows, fetch nothing
python3 -m gfd_data.smoke_era5 --clean              # remove what the test wrote
```

### Reading the build output

The build prints a report, not just files. Worth checking every time:

- `zero-target share` — **94,30% tropis, 97,00% subtropis** (measured, build of
  2026-09-06). Earlier drafts estimated ">99%" and were wrong. The conclusion is
  unchanged — predicting zero everywhere still explains most of the variance —
  but there are ~105 000 non-zero tropis cell-hours and ~99 000 subtropis
- `!! at hourly resolution the target is a COUNT process` — read it, every time
- `NO DATA for N months` — months with no records at all, excluded rather than
  zero-filled. Currently 3 for subtropis (2021-03, 2022-12, 2024-02); see RUNBOOK
  step 2, where 2021-03 is a proven MERLIN outage. There is no "dropping N months
  below coverage" line, because `MIN_COVERAGE = 0.0` switches that filter off —
  see RUNBOOK "Decisions"
- `months covered` — day-coverage per month. **Tropis averages 86%, subtropis
  59%**; the two domains are not observed to a comparable standard, which matters
  for the cross-domain comparison. Low values mean detector gaps, and with the
  gate off they are kept
- `N native points -> M cells` — regridding; `0% still empty` is what you want
- `!! N of M cells have ZERO flashes` — sea, or beyond detector range. Check
  *which* before assuming sea: six tropis cells are empty across all seven years
  and four of them are the northern coastal row near Jakarta and Cirebon, which
  is not lightning-free. That points at the box reaching past the LDS network's
  useful range rather than at water
- `!! absent features: [...]` — a predictor column that never arrived. Currently
  `KX` for subtropis, unexplained; see RUNBOOK step 4e
- `missing-value share by feature` — read before modelling

## The modelling experiment (`modelling/`)

Reads one processed table per domain, builds a single shared split and
preprocessing chain, fits a QNN and a parameter-matched classical NN on it, and
runs the cross-domain test in both directions.

```bash
cd modelling
python3 -m gfd_model.experiment --smoke       # seconds; plumbing only
python3 -m gfd_model.experiment --estimate    # project a full run's runtime
python3 -m gfd_model.experiment               # the real thing
```

Results go to `results/<timestamp>_<tag>.json` with a snapshot of `mconfig`, the
`.meta.json` of the table that was read, and every metric (F-05).

`GFD_DATA_DIR` overrides where processed tables are read from — used to point at
synthetic tables during development without editing code.

**Two things to know before running it:**

- `mconfig.FREQ_SLUG` is `"monthly"` while the pipeline builds `"hourly"`. Both
  defaults are argued for in their own docstrings, but they do not currently
  meet, so a fresh pipeline build plus a default experiment run gives
  `FileNotFoundError`. Pick one explicitly with `--freq`.
- Everything in `results/` so far was computed on synthetic tables. Check
  `build_meta.synthetic` before believing a number.

## Data

Nothing under either `data/` directory is committed.

```
dataset-pipeline/data/
├── raw/            source files, never edited
│   ├── pln/        PLN Puslitbang .xlsx (via supervisors — not public)
│   ├── merlin/     KSC archive .csv exports (89 files; 5 returned no usable
│   │               data and are kept as provenance — RUNBOOK step 2)
│   ├── power/      NASA POWER .json responses (591 files)

```

The PLN records were obtained through the supervisors and are not to be
redistributed. `data/raw/` is irreplaceable; `data/processed/` is regenerated by
one command.
