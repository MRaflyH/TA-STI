# Tugas Akhir — GFD Prediction with Quantum Machine Learning

Ground flash density (GFD) prediction for tropical (West Java) and subtropical
(Florida) domains, using a variational quantum neural network in Qiskit, plus
the data pipeline that builds its training tables.

Muhammad Rafly (18222067) — Sistem dan Teknologi Informasi, STEI ITB (II4092).

Two things are worked on independently: the **thesis document** (`paper/`) and
the **code** (`code/`).

2. `code/pipeline/data/raw/` is precious and irreplaceable — the PLN records
   are not public and were obtained through the supervisors. `data/processed/`
   is regenerated by one command and safe to delete. Neither is in git.
3. `code/modelling/` was deliberately emptied and is being rewritten from
   scratch. Nothing that used to be in it carries forward — including every
   number in the old `results/`, which were computed on synthetic tables.

## Environment

**One environment for the whole project.** The pipeline and the modelling code
previously had separate `requirements.txt` files, because installing Qiskit
could otherwise disturb a download that was mid-flight. All four acquisitions
are complete, so that reason has expired, and a single pinned environment is
what NF-02 (reproducibility) actually asks for.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Verified on Python 3.13.7. Python 3.10 is the floor, because
`qiskit-machine-learning` 0.9 dropped 3.9.

Regenerate the lock after any change: `pip freeze > environment-lock.txt`

## The thesis (`paper/Rafly TA/`)

XeLaTeX with Biber. `pdflatex` and `bibtex` will not work.

```bash
brew install --cask mactex-no-gui
```

The full distribution, not BasicTeX — the preamble loads `algorithm`,
`biblatex-chicago`, `threeparttable`, `datetime2-bahasai` and others that
BasicTeX does not ship. Open a new terminal afterwards so `xelatex` is on the
PATH. `biber` and `latexmk` come with it, and `\setmainfont{Times New Roman}`
resolves from macOS system fonts.

Compile from the directory holding `TA.tex` — not a subdirectory, since every
`\input` and `images/` path is relative to it:

```bash
cd "paper/Rafly TA"
latexmk -xelatex -file-line-error -interaction=nonstopmode TA.tex
```

By hand it is the same four passes in a fixed order:

```bash
xelatex TA.tex
biber TA
xelatex TA.tex
xelatex TA.tex
```

`latexmk -C TA.tex` clears the build state if a compile starts behaving oddly.

`TA.tex` drives the Tugas Akhir report (II4092, Bab I–VII).
`paper/Rafly Final Proposal/ProposalTA.tex` is the proposal (II4091, Bab I–V) —
different geometry, frontmatter, and float conventions, so check which one you
are editing before matching a convention.

## The dataset pipeline (`code/pipeline/`)

Reads lightning strike records and meteorological data from four sources,
aggregates everything onto a common 0,5° grid at the resolution set by
`config.TIME_FREQ` — currently **hourly** — and writes one table per climate
domain.

| Source | Role | Domain | Status |
|---|---|---|---|
| PLN Puslitbang LDS | strike records → GFD target | tropis | complete, 2018–2024, 2.242.100 CG strikes |
| NASA MERLIN (KSC archive) | strike records → GFD target | subtropis | complete, 89 exports, 5.301.491 strikes — 5 exports returned nothing, 3 months missing |
| NASA POWER | surface meteorology predictors | both | complete, 591 files |
| ERA5 (Copernicus CDS) | thermodynamic predictors | both | complete, 168 files — `KX` absent from subtropis |

Both processed tables are built: `gfd_tropis_hourly.parquet` (1.841.040 rows,
14 features) and `gfd_subtropis_hourly.parquet` (3.314.304 rows, 13 features).
The one-column difference is the missing `KX`, so the two domains do **not**
currently present the same feature set to a cross-domain experiment.

Full acquisition instructions, request counts, and the validation log are in
`RUNBOOK.md`. Read it before running anything that costs network requests — the
POWER fetch is ~590 requests and the ERA5 fetch is 168 queued ones.

### Running

Every command runs from `code/pipeline/src/`, with the venv active. Running
from the repo root gives `ModuleNotFoundError: No module named 'gfd_data'`.

```bash
cd code/pipeline/src

python3 -m gfd_data.smoke_lightning
python3 -m gfd_data.merlin_download --start 2018-01-01 --end 2024-12-31
python3 -m gfd_data.smoke_power
python3 -m gfd_data.power
python3 -m gfd_data.smoke_era5
python3 -m gfd_data.era5
python3 -m gfd_data.smoke_build
python3 -m gfd_data.build
```

MERLIN needs a device-level VPN with a US exit. ERA5 needs `~/.cdsapirc`; see
RUNBOOK step 4. Downloads cache by filename, so re-running skips whatever
already succeeded. PLN workbooks go into `data/raw/pln/` by hand.

Output: `data/processed/gfd_<domain>_<resolution>.parquet` and `.meta.json`, a
config snapshot so the build can be replayed. A `.csv` mirror is written only
below 500 000 rows, or with `--force-csv`.

### Useful flags

### Reading the build output

The build prints a report, not just files. Worth checking every time:

- `zero-target share` — **94,30% tropis, 97,00% subtropis** (measured, build of
  2026-09-06). Earlier drafts estimated ">99%" and were wrong. The conclusion is
  unchanged — predicting zero everywhere still explains most of the variance —
  but there are ~105.000 non-zero tropis cell-hours and ~99.000 subtropis
- `!! at hourly resolution the target is a COUNT process` — read it, every time
- `NO DATA for N months` — months with no records at all, excluded rather than
  zero-filled. Currently 3 for subtropis (2021-03, 2022-12, 2024-02); RUNBOOK
  step 2 records 2021-03 as a proven MERLIN outage. There is no "dropping N
  months below coverage" line, because `MIN_COVERAGE = 0.0` switches that filter
  off — see RUNBOOK "Decisions"
- `months below 90%` — **26 of 84 tropis, 56 of 81 subtropis**, all kept.
  READ THE MONTHLY TABLE, NOT THE AVERAGE. Coverage tracks the lightning season
  in both domains: subtropis sits at 90–100% every Jun–Sep and 3–25% every
  Dec–Mar; tropis dips the same way through the Jul–Sep dry season. The proxy
  is "a day with at least one strike somewhere in the domain is a day the
  network was up", so in a genuinely quiet month a working detector and a dead
  one look identical. `coverage` therefore measures climatology as much as
  uptime, and is correlated with the target. Do not weight or filter on it
  without saying so — down-weighting low-coverage rows preferentially removes
  low-activity periods and inflates apparent performance. This belongs in Bab IV
  as a limitation, not as a preprocessing step
- `N native points -> M cells` — regridding; `0% still empty` is what you want
- `!! N of M cells have ZERO flashes` — sea, or beyond detector range. Check
  *which* before assuming sea: six tropis cells are empty across all seven years
  and four of them are the northern coastal row near Jakarta and Cirebon, which
  is not lightning-free. That points at the box reaching past the LDS network's
  useful range rather than at water
- `!! absent features: [...]` — currently `KX` for subtropis; RUNBOOK step 4e
- `missing-value share by feature` — read before modelling

## The modelling experiment (`code/modelling/`)

**Currently empty, and being rewritten from scratch.**

The previous implementation compared a VQC-based QNN against a
parameter-matched classical NN, with a cross-domain test in both directions. It
was removed deliberately so the modelling work could be restarted rather than
patched. Its history is in git if a specific decision needs recovering.

Two constraints survive the rewrite because they come from outside it:

- `RANDOM_SEED = 18222067` is shared with `gfd_data.config` on purpose, so
  "seed 18222067" means one thing across the project (NF-02).
- F-05 asks that an experiment be replayable, which means an experiment config
  must record the build's `.meta.json` — the regridding, temporal-aggregation,
  coverage, quality-filter, flash-versus-stroke and land-mask choices — not just
  the model hyperparameters.
